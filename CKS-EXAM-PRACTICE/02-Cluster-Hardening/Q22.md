# Q22 — Cluster Hardening

The `reporting` ServiceAccount in namespace `batch-jobs` currently auto-mounts its API token into every pod that uses it, even though most of those pods never call the API. Disable automatic token mounting on the ServiceAccount, then fix the one Pod (`report-generator`) that genuinely needs the token by mounting it explicitly via a read-only projected volume.

<details><summary>Solution</summary>

```bash
kubectl patch serviceaccount reporting -n batch-jobs \
  -p '{"automountServiceAccountToken": false}'
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: report-generator
  namespace: batch-jobs
spec:
  serviceAccountName: reporting
  automountServiceAccountToken: false
  containers:
  - name: app
    image: myregistry.io/report-generator:1.0
    volumeMounts:
    - name: sa-token
      mountPath: /var/run/secrets/tokens
      readOnly: true
  volumes:
  - name: sa-token
    projected:
      sources:
      - serviceAccountToken:
          path: token
          expirationSeconds: 3600
```
</details>
