# Q25 — Minimize Microservice Vulnerabilities

Namespace `fintech` enforces the `restricted` Pod Security Standard. A Deployment `ledger-api` is being rejected at admission. Fix the Pod template so it becomes compliant.

<details><summary>Solution</summary>

`restricted` requires (among other things): no privilege escalation, all capabilities dropped, a non-root user, `RuntimeDefault`/`Localhost` seccomp profile, and no host namespaces/volumes.

```yaml
spec:
  template:
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 10001
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: ledger-api
        image: myregistry.io/ledger-api:3.2
        securityContext:
          allowPrivilegeEscalation: false
          readOnlyRootFilesystem: true
          capabilities:
            drop: ["ALL"]
```
```bash
kubectl apply -f ledger-api-deployment.yaml
kubectl get pods -n fintech -l app=ledger-api
```
