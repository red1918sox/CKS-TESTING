# Q27 — Monitoring, Logging & Runtime Security

Write a Falco rule that detects any process inside a container opening `/dev/mem` (a classic container-escape / privilege-escalation indicator). Then, given an alert fires for a pod, show how to identify its owning Deployment and safely neutralize it by scaling to 0 replicas (without deleting it, so it can be investigated).

<details><summary>Solution</summary>

```yaml
- rule: Read Sensitive Device Memory
  desc: Detect a process opening /dev/mem inside a container
  condition: >
    open_read and container and
    fd.name = /dev/mem
  output: >
    Sensitive device /dev/mem opened in container
    (user=%user.name container=%container.name image=%container.image.repository
    command=%proc.cmdline)
  priority: CRITICAL
```

```bash
# Identify the offending pod from the alert, then find its Deployment
kubectl get pod <pod-name> -n <namespace> -o jsonpath='{.metadata.ownerReferences[0].name}'
# -> ReplicaSet name; trace that RS to its Deployment
kubectl get rs <replicaset-name> -n <namespace> -o jsonpath='{.metadata.ownerReferences[0].name}'

# Neutralize without deleting (preserve for forensics)
kubectl scale deployment <deployment-name> -n <namespace> --replicas=0
```
